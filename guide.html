01 突击学习路线

您的两到四周备考路径

每天建议30-45分钟，完整模考另留120分钟。您已通过OPC，先做20题诊断定位新增薄弱点；操作基础先刷后补，企业后台、WMA、交付方法和安全责任不能略过。

第一周：打通新增知识

D1规则+20题诊断；D2方法论与Echo/Delta；D3产品选型与工程；D4企业后台和WMA；D5真需求与一线采纳；D6PEV、验收和成熟度；D7沉淀、安全与错题回看。每天回官方对应章核对不熟术语。

第二周：按模块验证

工作日每天约20题，核对解析并写一句错因；周末第一次120分钟模考，按模块分数回补。同步做一个小实操：用真实授权资料跑一轮原型、实证、验证，留下一个Skill草稿及一张验收卡。两周就考试时，在最后几天用官方15题校准。

第三至四周：稳定表现

第三周读CFO案例和FAQ，把每个案例动作对应到PEV、四维验收、溯源与门禁；完成第二轮模考和错题重练。第四周只补弱项、做随机卷、核对产品细节及考务；考前2-3天做官方模拟题校准语言与难度。时间不足可合并，不必为满四周机械刷熟题。

考前自检

建议连续两轮原创模考达到85分，并能解释错项；这是自定备考目标，不是通过率保证。官方模拟题机会有限，建议先学后测。正式考试与预约证件要求以通知为准。

02 概览与方法论 · 11.5%

官方占比 11.5% · 回官方第1章核对 · 本站题库 #1-12

角色的两份产出

FDE 深入客户现场，用工程方式解决业务问题，同时向组织回流可复用能力。客户得到可运行结果，组织得到 Skill、连接器、知识包、评测集等资产。驻场地点、交付速度和材料页数，都不能单独证明 FDE 模式成立。

真假试金石

结项后检查组织新增了什么、下一位同事能否接手、下个同类场景能否少投入。个人懂了而组织没留下能力，只算个人经验积累。更硬的判断是：在价值相当、场景可比的条件下，同类项目的现场投入是否持续下降。

Echo 与 Delta

Echo 负责判断该做什么：识别需求、理解行业、确定路径和验收。Delta 负责把它做出来：编码、配置、集成、测试与排错。它们是能力侧，不强制对应两个人。AI 降低部分执行成本，使方向判断更重要；不写代码也要能亲手跑出原型。

三个陷阱

伪 FDE：人在现场但没有沉淀。传话式 FDE：只转述需求，现场判断与实现反复脱节。考核错位：只看人天、速度、满意度，忽略资产有效复用。后方工程支持可以存在，现场判断与快速反馈不能丢失。

组织与考核

销售、交付、研发单一归属均有代价；课程建议保持产品连接并贴近客户。考核需同时覆盖交付价值与能力沉淀。课程中的 50%/50% 是设计示例，不是所有企业的强制配比；题目应先看双目标是否存在。

选择题判断法

遇到“客户满意所以一定是真 FDE”，补问组织资产；遇到“写很多总结所以沉淀成功”，补问第二场景调用；遇到“只能全栈工程师做”，区分判断侧与执行侧。交付与沉淀不是二选一。

03 腾讯云 AI 体系矩阵 · 8.5%

官方占比 8.5% · 回官方第2章核对 · 本站题库 #13-24

选型先问三件事

谁来用、做什么、与什么系统打通。先明确需求与边界，再选产品；复杂场景可以组合。不要因为某产品能生成文字，就把它等同于其他所有 AI 产品。

四款产品分工

WorkBuddy：面向业务岗位的办公任务与知识协作；CodeBuddy：面向研发工作流的编码、测试和调试；ADP：定制企业 AI 应用、工作流及系统集成的平台；Miora：成套多模态视觉创意。这里比较的是主定位，不是宣称产品完全不能跨界。

专家、助理、团队

专家封装岗位能力；助理承载常驻执行任务；团队提供协作空间与资产复用。由个人提效走向组织生产力。云端托管任务与本地电脑任务的运行条件不同，不要把所有自动化都理解成关电脑后仍可运行。

四类资产互相配合

Skill 管做事步骤；连接器管系统访问；资料库管专业内容与上下文；专家把人设、技能和展示信息打成岗位角色。单独一段人设提示词不等于完整的可复用业务能力。

客户落地四层门槛

理解需求 → 翻译需求 → 零到一搭建 → 一到 N 调优。用户说得出痛点，不等于已转化为输入、输出、规则和指标。原型能搭出来，也不等于已经解决采纳和持续运营。

平台、工具、生态

平台层封装模型、知识库、连接与治理能力；工具层承接办公、工作流、评测、模板等执行；生态层提供伙伴方法论与交付规范。评测验证质量，自动化触发运行，两者不能互相替代。

04 人工智能工程 · 10%

官方占比 10% · 回官方第3章核对 · 本站题库 #25-36

Prompt 五要素

角色、指令、约束、示例、输出格式。把模糊请求改成可执行规格：任务是什么、只能依赖哪些资料、缺信息怎么办、产物有哪些字段。格式契约与证据要求比“请务必专业”更能减少歧义。

上下文选而不是全塞

保留系统规则与当前任务；历史可滚动摘要；工具结果裁剪无关字段；知识通过检索取相关片段。为输出预留预算。关键证据保留可追溯原文，不把压缩后的猜测当事实。Top K 是可调参数，不是越大越好。

Harness 五件套

工具接入、输入输出契约、错误处理、护栏门禁、可观测性。模型会回答不代表系统能交付；要对超时、空结果、格式不符、重试失败和权限不足定义明确路径。

Loop 四环节与停止条件

感知 → 规划 → 行动 → 反思。提前定义任务完成、步数上限、总时限、连续错误上限及人工关卡。高风险动作前暂停；等待审批超时不能默认为同意。重复重试而不增加证据，是应停止并升级的信号。

MCP 身份与凭据

先判断以用户还是服务身份操作，再选授权流程。交互式接入优先考虑平台支持的 OAuth；无人值守按服务支持选择受管凭据或客户端凭证。PAT 是某些服务提供的凭据形式，不能说成 MCP 必须使用 PAT；OAuth 版本不等同于是否有人在场。令牌要安全存储、轮换、撤销、审计。

MCP 排障顺序

网络出口与依赖可用性 → 用户级/项目级配置范围 → 凭据有效性与权限范围。401 常先看认证；403 常先看授权，也结合服务返回细节。课程的入门口诀不能替代真实错误日志。项目配置在另一个目录不可用，不该靠扩大权限解决。

05 WorkBuddy 上手实操 · 10%

官方占比 10% · 回官方第4章核对 · 本站题库 #37-48

第一条任务就可验收

告诉 WorkBuddy 处理哪些已授权文件、完成哪一步、输出什么产物和先验什么。例如先检查表格字段和缺失情况，再统计并出报告。一个客户场景开独立任务，避免不同项目上下文混入。产物面板用于检查实际文件。

Skill 两条路线

现成技能可从 SkillHub 查找安装；自建用 skill-creator，把重复规则固化为 SKILL.md，可附脚本、参考和模板。description 写明业务词与触发场景；课程要求自建可迭代技能带 agent_created: true。企业上传还需企业包元数据，不能把个人目录直接当企业发布完成。

技能不触发怎么查

先检查 description 是否具体，再用技能名手动调用。手动可用而自动不匹配，优先修触发描述；手动也失败，检查步骤、依赖、资源路径。不是把所有技能全文放入每次对话，也不是先增加模型权限。

专家从定位到验证

先定角色、对象、核心能力、行业与推荐提问，再编写人设、能力边界、流程、输出规范并挂接技能。清理占位符、校验后注册或打包。企业专家需管理员上传、启用并下发，标识发布后不可改的版本规则要提前确认。

连接器与自动化

连接器把外部系统纳入授权访问；用户级 MCP 对各项目通用，项目级只在该项目生效。周期任务要明确触发、运行环境、凭据、失败通知和人工关卡。本地自动化依赖本地运行条件，长时云任务要用对应托管能力。

四小时演练

第一小时选一个真实小场景并体检数据；第二小时得到可重跑原型；第三小时固化反复交代的规则；第四小时包装专家并验证自动化。演练出口是可检查产物，不是看完视频。涉及外发或写入时先验证授权与门禁。

06 企业后台与 WMA 配置 · 10%

官方占比 10% · 回官方第5章核对 · 本站题库 #49-60

三个端

客户端让员工用 AI；企业后台管理成员、资源、策略、用量与审计；WMA（WorkBuddy Managed Agents）提供云端托管运行。共享身份与治理底座，不意味着所有成员自动有权访问全部数据。

部署先看边界

旗舰版对应共享 VPC，专享版对应专享 VPC，私有化企业版对应企业私有部署（课程口径）。先问能否出内网、需要何种隔离、谁负责运维，再比较能力与成本。云端专享隔离不等于部署在客户机房；私有化不等于不用审计或维护。

成员和能力下发

成员可通过统一身份同步或邀请审核加入。能力流程是上传 → 分类 → 策略 → 到人，并用真实成员验证。个人自定义技能不自动共享；企业 Skill 包需 SKILL.md 与 manifest.yaml 等课程指定元数据，按 .zip 上传。上传权限与使用权限是两条策略。

权限问题分层查

课程规则：黑名单优先于白名单，再看默认策略；默认行为可能被管理员改变。专家启用状态独立于下发策略；内置市场专家与企业自建专家的治理范围不同。最终看后台权限查询，不能把课程默认允许当成应给敏感资料全员开放的建议。

知识库与连接器

知识库需完成索引、可见范围正确，在课程客户端流程中用 @ 引用。编码或解析失败不靠调 Prompt 修复。连接器先确认认证类型，以其配置或实际授权的第三方身份访问；平台下发可见不意味着第三方业务授权自动扩大。

Agent / Runtime / Session

Agent 是能力定义，Runtime 是执行环境，Session 是独立会话上下文。分享接入链接与 API 是两种交付方式；会话之间应隔离。课程不同段落对 Runtime/Session 的数量关系描述不一，本资料不考一对一或一对多的绝对断言，重点记清职责。

配置与执行的积分

按课程口径：浏览、上传、管理等配置不消耗积分；任务执行、引用知识后的生成、外部数据理解汇总及评测会产生相应消耗。不能由此推出外部 API、基础设施和合同费用全免费。按试运行用量估算预算，设置告警；版本额度和价目考前回官方复核。

度量与运维

观察专家与知识库是否被真实调用，结合留存和业务指标，不能只看登录或总对话量。审计记录成员、时间、对象、操作和结果。课程提到度量同步约 15 分钟、空闲会话约 10 分钟休眠，属于版本细节；删除 Session 会清除记录与文件，应先备份必要交付物。

按课程版本记的规格

旗舰/专享课程额度为每人每月2000 Credits、团队共享。知识库单文件不超过30 MB、压缩包不超过300 MB，编码UTF-8或GBK；Top K建议3-5，Score Threshold建议0-0.5。企业Skill的manifest.yaml列出name、version、description、category、author。WMA Manifest最小必需id、name、manifestVersion；system_prompt与system_prompt_file互斥。这些是课程版本细节，不是跨平台恒定规则。

07 进场：挖真需求 · 10%

官方占比 10% · 回官方第6章核对 · 本站题库 #61-72

访谈往下挖三层

哪一步出问题 → 谁在真正使用 → 什么算成功。客户提出“要 RAG”通常是方案描述，不是已验证需求。访谈业务负责人、一线用户和 IT，确认节点、基线、目标、数据和责任人，再承诺范围。

识别隐性流程

正式 SOP 表示规定做法，未必等于实际做法。跟着一线走一遍、追问最近失败案例、比较新老员工处理差异。把有效经验显性化，但不把违规或低效绕行原样固化。客户信任与授权边界也要守住。

Demo 用来对齐

先用可交互原型让业务方挑错，再用真实授权数据暴露边界，最后用对照数据讨论价值。Demo 不能替代冻结样本的验收。课程场景 Demo 的 L1/L2/L3 是展示层次，不要与第七章项目成熟度 L0-L4 混为一套。

破抵触三步法

分别对齐管理层、中层和一线预期 → 建小范围公平对照组 → 先让 AI 对员工本人省力、有收益。要明确责任与人工复核，不替客户保证“永不裁员”。中层不配合也可能提示场景本身价值不足，需调查原因。

场景优先级六维

业务关注、痛点、数据基础、可量化程度、技术可行性、流程阻力。前四项先判断值得做，后两项帮助判断实施条件和顺序。可做不等于该做；不在负责人重要事项内或接口无排期，都可能让项目空转。

教育场景的迁移

可从真实教研任务、资料整理、草稿生成等较可控环节试点，保留教师审核并保护学生数据。不是“教育全都低风险”，涉及成绩、升学等重大判断仍须专业人员终审。工作营应留下可运行应用、可复用技能和日常使用习惯。

08 交付：做成且验得动 · 10%

官方占比 10% · 回官方第7章核对 · 本站题库 #73-84

PEV 三步闭环

P=Prototype，原型用于暴露分歧；E=Evidence，真实数据和真实用户形成实证；V=Validation，对照预设验收标准验证。测试未达标回去修根因，不临时降低标准求过关。周期数字是建议，阶段目的比天数重要。

四维验收

效果：正确、相关、证据可靠；效率：耗时、人效、成本与尾延迟；采纳：活跃、使用深度、持续留存；合规：拒答、溯源、接管等。进场即定义指标、分母、样本、阈值、负责人和通过规则。示例 85% 或 3 秒不是所有项目统一标准。

三条兜底

无依据时拒答优于胡答；结论可追溯到资料或调用证据；用户能转人工并带上上下文。拒答率不是越低越好，要区分应答问题被误拒、无答案问题正确拒答和总体拒答比例。

成熟度 L0-L4

L0 场景识别；L1 原型验证；L2 试点运行；L3 生产部署；L4 规模扩展。PEV 管推进节奏，L0-L4 管项目位置。L1 到 L2 常卡在脏数据、真实权限和用户采纳，优先早接真实数据、早通权限、找种子用户。

范围控制四纪律

一次只解一个可衡量问题；不确定性不传下游；新增需求换出已有范围或走变更；先窄而深，再扩展。不把“顺手加一个”变成无限承诺。未验证阶段扩大全公司会同时放大技术和组织问题。

Land and Expand

先把小场景做深，用可信对照数据建立信任，再向相关场景扩展。扩展前看质量、采纳、运维和复制成本。并非每个项目必须达到 L4；风险未收敛时暂停或退回，属于负责任的交付决策。

09 沉淀：组织资产 · 10.5%

官方占比 10.5% · 回官方第8章核对 · 本站题库 #85-96

总结不等于资产

项目总结依赖当时上下文；资产应让未参与项目的人直接调用。把共性流程、触发条件、输入输出和验证方法写清，再在第二个相似场景使用并修正；未经跨场景验证先标成草稿。

双向蒸馏

面向客户留下可持续使用、维护和交接的操作资产；面向产品/组织留下跨项目复用的能力。只留客户系统会重复定制，只留内部资产会让客户离开你就用不了。边解决问题边沉淀，别等结项追忆。

方法与特化分层

共性步骤进 Skill；客户字段、接口地址、凭据和业务参数留在隔离配置或受管资料中。不要把客户 A 的私有数据和阈值写死进共享模板。版本、作者、权限、检索与反馈渠道要齐全。

三态溯源

知识库实证：能回原文；接口实证：能复查调用与时间；AI 推断：缺客户侧直接证据，必须显式区分。实证可追溯不等于自动绝对正确，还要检查来源版本、权限和冲突。推断不能冒充真实记录。

四条红线

不碰未授权数据；不替客户做终审决策；不隐藏失败样本；不承诺未验证效果。它们约束职业行为。涉及金钱、人员、法律责任的决定由有责任能力的人确认留痕，不因模型强大就省略。

成本曲线与冷启动

复用有前期投入，收益需看后续同类项目的边际投入。课程倍数为量级示意，部分累计示例不一致，不当成财务定律。冷启动：聚焦一个场景、选愿共建客户、首单就设沉淀交付物、定价机制不惩罚效率提升。

信任四问与载体

贡献：署名溯源；收益：先帮贡献者省力；边界：只沉淀应授权的岗位方法；安全感：让贡献者参与判断与校验。载体包括通用 Skill 库、隔离的客户资料库、脱敏踩坑卡。衡量有效复用与反馈，不用文件数量代替价值。

10 FDE 养成计划 · 10%

官方占比 10% · 回官方第9章核对 · 本站题库 #97-108

总原则

WorkBuddy 放大人的能力，不能代替人承担责任。练习应成为真实交付物的初稿；培训按项目里程碑调整；工具给依据，人做终审。培养计划是实践路径，不能把参加培训等同于考试已通过。

四阶段

课程基准：W1-W3 立项，W4-W6 方案设计，W7-W9 开发推进，W10-W12 项目管理。依次形成立项卡、可执行 PRD、可运行 Demo、复盘与组织资产包。12 周是课程计划基准，不是对任何客户项目的交期承诺。

Gate 1 与 Gate 2

W3 看真需求、量化价值、风险假设；W6 看 PRD 的不确定性说明、异常与人工兜底、验收评测口径、MVP 边界及开发可理解性。文档完备不等于真实业务假设已被 POC 证明。

Gate 3 与 Gate 4

W9 看核心假设验证、运行中的 Demo、由人决定的迭代优先级；W12 看验收、具体复盘、能力回灌到企业专家与知识库。评审技能给结构化建议，Go/No-Go 最终由教练或责任人裁决。未过就补，不走形式。

教练闭环

课前看上次产物和准备条件；课中观察并纠偏；课后审阅交付物；阶段末做 Gate 评审与复盘。教练自己要能操作工具与跑通原型，不能只念教材。边界不越位，关卡不放水。

工具能帮与人要懂

工具能拆任务、生成接口草案、画相关方地图、执行评测；软件工程判断、相关方协商、统计与评测设计仍需人掌握。会点“跑评测”不等于会设计评测集。AI Coding 后仍须 review、测试与回归。

11 安全治理与护栏 · 9.5%

官方占比 9.5% · 回官方第10章核对 · 本站题库 #109-120

约束三层

数据层管什么可进出；能力层管权限与动作；过程层管日志、评测与责任留痕。三类护栏说检查位置，三层约束说治理职责，是两种划分，不能直接一一替换。

数据和权限

先确认数据边界、系统准入、授权颗粒度，再选部署。只读优先、作用域收窄、敏感字段保护。通过私有化或内网不自动保证安全：越权、外发、日志泄密、误操作仍需控制。

三类护栏

提示词护栏在输入进入模型前检查；工具护栏在动作执行前验证工具、参数和风险；连接器护栏在访问外部系统时校验身份、域名与数据范围。仅在 Prompt 写“不要泄密”不足以替代真实的权限与执行门禁。

审计三段式

Prompt / Tool / Response 三段用同一 request_id 串联。保存可审计输入、工具参数与结果、最终输出、版本和审批记录；日志敏感字段脱敏并限权。需要操作证据与必要决策记录，不要求暴露模型私有思维链。

评测门槛

先定指标、阈值和通过规则，再上线与回归。覆盖正常、无答案、越权、攻击、失败与边界样本。冻结回归集用于版本可比，新留出集检验泛化；不能把训练调优数据当独立验收。课程 90%、8 秒等是示例值。

人工兜底三位置

入口：缺材料与异常输入时补信息或拒答；过程：重复失败或超限时停并升级；出口：高风险结论前人工确认，无依据推断显式标注。操作按可逆性和影响面分级，不能因为全程自动化更快就绕过审批。

上线八问

数据去向是否清楚？连接器是否最小授权？谁能用何能力已验证？不可逆动作有门禁？日志能还原链路？评测门槛已达？无依据会拒答吗？终审是否由人且留痕？每个回答都要有证据；发现缺口先补齐再放量。

12 CFO审核：用案例串通全部方法

依据：官方第11章CFO案例；综合应用于方法、交付与治理，不另加第11个考纲权重。

先证明，再放权

CFO 结算审核先做人机平行评测：同样输入分别审，人工维持线上最终裁决。记录附件、规则版本、Agent 运行轨迹与人机分歧，再由专家核对证据。人机一致不自动代表正确，历史人工结论也可能有误或随版本变化。

七步审核 SOP

真实材料摸底 → OCR/全要素抽取 → 构建历史评测集 → 抽取规则候选并由专家 Review → 最小 Workflow + Skill → 业务可读的证据展示 → 冻结回放、迭代和受控上线。材料输入、规则判断、证据解释、人工结论、持续反馈齐备，才有迁移基础。

评测和迭代分工

评测回放空间负责采集、对比、分歧标记与回归；迭代引擎吸收反馈、生成候选、验证修复。候选版本不能自动冒充已批准版本；保留版本、发布建议、回滚依据与责任人。

六类可复用资产

数据采集模块；评测回放空间；审核领域 SOP；OCR/全要素抽取；反馈驱动的 Agent 能力迭代；业务可读可视化。评审同时关注准确性、稳定性、Token 成本与 ROI。案例中的提升数字只描述特定案例，不承诺可复制收益。

13 考前易混清单

不要学错认证

本资料对应 CID/TCCP 职业认证，120 分钟。ADP FDE 是另一项专项认证，其 90 分钟与七模块权重不能套用。

数字分三类

考试规则可直接记；课程产品规格按核验版本记；项目示例值只理解方法。12 周、四 Gate 属课程框架；85% 准确率、3 秒延迟、若干倍成本不成为所有客户的统一验收线。

OAuth 不要背成绝对对应

“有人 OAuth、无人 PAT”只是初步速查；授权身份、grant 流程、服务器支持与协议版本需分开。课程自身已有修正说明，题库避免考“2.1 必须有人”这样的绝对句。

权限默认不是安全建议

课程的默认允许描述不能覆盖自定义默认拒绝策略、资源停用状态、第三方 ACL。白名单与黑名单冲突时先看黑名单，之后用权限查询验证；不为排错随意扩大敏感数据权限。

成本和运行别混淆

平台配置不扣积分，不等于基础设施与外部服务没有费用；WMA 常驻不等于每个 Session 一直占用活跃算力；本地任务和云端托管的在线条件不同。

安全术语别串

约束三层=数据/能力/过程；三护栏=提示词/工具/连接器；三态溯源=知识库实证/接口实证/AI 推断；验收四维=效果/效率/采纳/合规。

14 一张可带回工作的交付模板

场景卡

用户是谁；流程卡在哪；现有基线；希望改善多少；数据来源及授权；不做什么；业务负责人、IT和种子用户是谁。若只有产品名没有以上内容，先回访谈。

验收卡

效果、效率、采纳、合规分别写指标、分母、样本集版本、阈值、统计窗口、通过规则与签字人。关键合规项单独设门禁，不用平均分掩盖。

实证卡

固定输入与版本，记录输出证据、工具轨迹、异常与人工判断；差异送专家复核；分清数据缺失、规则冲突、检索错误、工具失败、模型推断和用户流程问题，再选择修复点。

资产卡

通用方法、客户参数、脱敏失败卡分别归档；写作者、版本、触发、输入输出、证据、反馈入口；在第二场景验证；维护批准版本和回滚方式。
